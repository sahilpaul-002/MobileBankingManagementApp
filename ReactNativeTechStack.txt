### My React Native Development Stack

I am developing a React Native application using **React Native + TypeScript + Expo**. When helping me with any task, use the following technology stack and conventions:

- **Navigation:** Expo Router with file-based routing, nested layouts, `Slot`, `Stack`, and `Tabs` where appropriate.
- **State management:** Redux Toolkit and React Redux.
- **API integration:** RTK Query for data fetching, caching, and request management; Axios for HTTP communication through a centralized API client where needed.
- **Styling:** NativeWind for Tailwind-style native styling, React Native `StyleSheet` when appropriate, and React Native Reusables for compatible reusable UI components.
- **Forms and validation:** React Hook Form and Zod.
- **Storage:** Expo SecureStore for sensitive credentials and tokens; AsyncStorage for non-sensitive persistent data.
- **Native UI:** React Native components such as `View`, `Text`, `Pressable`, `TextInput`, `Image`, `ScrollView`, `FlatList`, and `SectionList`.
- **Development and debugging:** Metro, Expo CLI, Android Studio, Android SDK, and Android Emulator.

**Development rules:**
1. Write strict, type-safe TypeScript and follow React Native and Expo best practices.
2. Prefer small, reusable components, custom hooks, utility functions, and maintainable code over unnecessarily large components.
3. Reuse my existing project architecture, dependencies, components, hooks, types, API clients, and styling conventions whenever possible.
4. Do not use web-only technologies such as `react-dom`, DOM APIs, browser-specific APIs (`window`, `document`, `sessionStorage`), traditional web CSS, Vite, React Router, or standard web shadcn/ui components.
5. Do not use web-oriented table libraries such as TanStack Table for native mobile data presentation; use `FlatList`, `SectionList`, or suitable mobile layouts instead.
6. Do not introduce additional libraries, duplicate existing functionality, or change the project architecture unless necessary.
7. Prefer Expo-compatible APIs and libraries. Use Kotlin or custom native Android modules only when a required native capability cannot be handled adequately by the existing React Native/Expo stack.
8. When teaching me, explain unfamiliar React Native concepts by relating them to my existing React and TypeScript knowledge. Explain the purpose of the code and introduce concepts step by step instead of assuming I already know native development.
9. When implementing a task, focus only on the requested component, feature, or concept. Do not generate unrelated application code or rewrite existing files unnecessarily.
10. If the solution depends on my existing project structure or code, ask for or inspect the relevant files before making assumptions. Provide precise changes and explain any new dependencies or configuration requirements.

Follow these instructions as the default context for my React Native development tasks, while adapting the implementation to the specific request.
